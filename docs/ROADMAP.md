# 大肥鱼 HOI4 · 下一阶段计划

> 当前 v1.3.0。核心已通：聊天、同局 AI、A 托管、连续托管、软件自动输入、本地规则规划 0 tokens、国策 effect。
> 但模板/训练/空海军任务仍未验证，自动执行的“控制台状态”还不稳。

## 原则

1. 先机制，后实现；
2. 先稳定，后智能；
3. 能 effect 做的才接；不能的明确说不能；
4. 每条功能必须有真实存档/干净测试环境证据；
5. 本地规则优先，模型只处理复杂判断。

## Phase 0：自动执行稳定性（最高优先）

问题：

- `~` 是切换键；如果控制台已经打开，自动执行会把它关掉，再输入就变成 Unknown command；
- 自动托管连续跑时，可能出现多周 backlog；
- 现在没有“控制台已关闭”的可靠判断。

要做：

- 自动执行前检测/确保控制台关闭；
- 失败时不盲目重试；
- 记录每次执行的 console 状态/截图证据；
- 增加“一次只跑一单”的锁；
- 20 次连续自动执行测试。

验收：

- 20 次自动 `run` 无 Unknown command；
- 每次只执行一单；
- 失败能明确报“控制台状态未知”，而不是静默输错。

## Phase 1：通用编制模板（先做 3 个）

状态：**阻塞**。v1.3.1 实测 `division_template` 放进 `eval_effect` 报
`Had errors compiling the effect`，后面的 state 也不执行。先保持模板功能关闭，
需要换实现（mod 包装/其他 effect/UI 自动化）后再开。

模板：

| id | 名称 | 组成 | 支援 |
|---|---|---|---|
| inf20 | DFY 步兵师 | 7 步兵 + 2 炮兵 | 工兵、炮兵 |
| marine20 | DFY 海军陆战队 | 7 海军陆战 + 2 炮兵 | 工兵、炮兵 |
| armor20 | DFY 装甲师 | 6 坦克 + 4 摩托化 | 工兵、维修 |

要做：

- 用官方 `division_template` effect；
- 一次只加一个模板；
- 干净测试存档验证“编制界面出现模板”；
- 失败时回滚/不写订单。

验收：

- 编制界面能看到 3 个模板；
- 无 error.log；
- 不声称“训练部队”，只声称“添加模板”。

## Phase 2：本周计划卡 + 国策分支

要做：

- 主界面固定“本周计划”卡：
  - 愿景；
  - 国策；
  - 三件事；
  - 执行/跳过。
- 国策列表按 x/y + prerequisite 分组；
- 过滤不可用/已完成的焦点；
- 参谋模式和普通模式共用。

验收：

- 不用翻聊天记录就能看到本周计划；
- 国策来自真实分支；
- 不选已完成的焦点。

## Phase 3：本地智能与预算

要做：

- 本地规则库：
  - 海军/工业/陆军/政治四类；
  - 国策关键词匹配；
  - 避免重复投资；
  - 低政治点/低稳定/低战争支持优先；
- token 预算：
  - 每日/每周上限；
  - 本地规划默认 0 token；
  - 模型规划手动开；
- 决策日志：本周为什么选这个。

验收：

- 连续 10 周本地托管 0 tokens；
- 模型只在手动要求/复杂目标时调用；
- 决策日志可回看。

## Phase 4：训练/空海军“一个动作”验证

只验证，不承诺全接管：

- 打开编制设计器，改一个营；
- 训练队列加一个师；
- 设置一个空军任务；
- 设置一个海军任务。

方式：

- 截图/OCR/鼠标点击；
- 每一步失败可回滚；
- 3/3 成功才继续。

验收：

- 一个动作 3 次成功；
- 不破坏存档；
- 失败明确报“UI 层不支持”。

## Phase 5：验收与发布

- 5 周连续托管，逐周记录；
- 更新 README/CHANGELOG/截图；
- 推 GitHub v1.x；
- 保留 HID 兜底，不默认要求硬件。

## 现在立刻做

2. Phase 1 模板目录 + 干净测试；

## 需要你配合

- 一个独立测试存档，不要拿主存档试模板；
- 测试时游戏用 `-debug_mode`；
- 模板/训练/任务要允许我看编制界面/截图；
- 连续托管时接受 API 费用（本地规划默认 0）。
